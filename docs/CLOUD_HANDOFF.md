# AFTERLIFE INC. 雲端接手說明

最後整理：2026-09-09

## 目前已可玩的內容

- 開場引導：翻牌 → 規則揭示 → 多段靈魂掉落 → 閘門結算。
- 重生後命運校準：圓環／八字／星形浮文，3 至 8 枚永久解鎖，鎖定位置影響路徑。
- 自動命運儀式：需星圖最末宇宙節點，收益刻意限制為手動計算的 58%。
- 12 張命運牌資料；12 張均有專屬生成卡面，前 10 張為初始卡池，另 2 張由特殊商店取得。
- 卡牌收藏（`C`）、靈魂圖鑑與背包（`I`）、36 節點星圖（`T`）。
- 神祉：阿斯特萊雅衣櫥與外觀資料（`G`）；另已生成 Selene、Orpheon 角色主視覺，尚未接入選角 UI。
- 特殊商店（`B`）：20 分鐘輪替、混合資源價格、永久遺物與一次性諭令。
- 每週規則與本機榮譽紀錄（`W`）。
- 設定（`O`）：教學重播、低閃爍偏好、UI 縮放設定保存。

Godot_v4.7.2-stable_win64.exe --headless --path . --editor --quit

## 雲端接續優先順序

1. 將 Selene、Orpheon 接到神祉選擇與獨立外觀資料；補神祉專屬視覺變體。
2. 擴充 v1.0 命運牌至至少 30 張；每張必須有資料、無文字生成卡面、收藏映射與取得方式。
3. 為六種靈魂製作個別生成外觀，並將稀有度視覺接入圖鑑。
4. 將掉落動畫由多段可視路徑升級成逐釘／閘門導向的物理或可重放模擬。
5. 建立完整場景載入模式的流程測試：新存檔 → 首局 → 重生 → 節印 → 結算。
6. 補音效、重新綁定、設定實際套用（目前 UI 縮放僅保存值）。
7. 安裝 GodotSteam 後，依 `STEAMWORKS_INTEGRATION.md` 實作 Steam Cloud 與 Leaderboard；目前 `SteamService` 僅是安全抽象層。
8. 平衡測試、存檔遷移、發行 Build。

## 重要規範

- 主畫面、卡面、星圖、角色、結算皆優先使用生成視覺；Godot 僅作透明互動與必要文字。
- 卡面不可嵌入文字，效果在翻開後顯示。
- 資源不可互相兌換；特殊商店可同時消耗多項資源。
- 不要以 Steam Leaderboard 當作通用資料庫。
